# venue-service — демо-заведение

Это **не часть площадки**. Это отдельный сервис, изображающий кассу реального
заведения: он живёт в своём каталоге, со своей БД и своими миграциями, а до
площадки достаёт ровно теми же путями, что доступны настоящему партнёру —
сгенерированным из спеки клиентом партнёрского API и топиком Kafka.

Зачем он нужен: без него интеграция «площадка ↔ заведение» осталась бы описанной
на словах. С ним каждый `docker compose up` проверяет её целиком — меню
приезжает в каталог через `POST /partner/menu`, заказ уезжает событием и
возвращается статусами.

## Почему у него нет входящих ручек

Заведение — headless. Наружу торчит только `/healthz` для compose: экран повара
понадобился бы единственно ради ручных `curl`, а проверить сервис можно и без
него — по состоянию его собственной базы и по статусам заказа на площадке.
Роль повара исполняет автопилот: он делает те же вызовы, что делал бы человек за
кассой.

## Что происходит при старте

1. Свои миграции (`venue/migrations`) применяет отдельный сервис
   `venue-migrator` — площадка про эту базу не знает и не создаёт её.
2. `GET /partner/me` — заведение узнаёт по ключу, кто оно на площадке, и в какой
   топик ему шлют заказы. Первые попытки ожидаемо получают `401`: ключ появляется
   в базе площадки на шаге `make seed`. Сервис повторяет попытку каждые
   `BOOTSTRAP_RETRY`.
3. `POST /partner/menu` — полная выгрузка своей номенклатуры
   (`venue/internal/menu/data.go`).
4. `POST /partner/shift/open` — смена открыта, заведение появилось в выдаче
   `GET /venues?open_now=true`.

Это первые три шага CJM заведения, и они проверяются на каждом запуске.

## Что происходит дальше

- **Консьюмер `kitchen.orders.v1`.** Заказ приходит событием, дедуп по
  `event_id` в таблице `processed_events` — повторная доставка не создаёт второй
  заказ на кухне. Позиции заказа списываются с собственных остатков заведения.
- **Автопилот.** Раз в `AUTOPILOT_INTERVAL` берёт заказы, у которых вышел срок
  текущего шага, и двигает их дальше: `accept` → `cooking` → `ready` →
  `handover`. Момент входа в состояние лежит в БД, а не в памяти процесса, поэтому перезапуск
  сервиса ничего не теряет. Заказ, который площадка отказалась двигать, не
  перетягивается: сервис спрашивает у неё текущий статус и записывает его себе.
- **Стоп-листы.** Когда собственный остаток блюда кончился, заведение снимает
  его с продажи на площадке через
  `PATCH /partner/menu/items/{external_id}`, и позиция уезжает в каталог как
  `is_available: false`. Когда остаток появился — возвращает обратно.
- **`handover` — конец зоны ответственности заведения.** Дальше заказ ведёт
  площадка: партнёрской ручки `deliver` нет и быть не должно.

## Схема его БД (`venue/migrations`)

| Таблица | Что хранит |
|---|---|
| `dishes` | номенклатура заведения: SKU, цена, остаток, продаётся ли |
| `incoming_orders` | заказы, пришедшие с площадки: `main_order_id`, состояние, момент входа в него, исходное событие |
| `processed_events` | отметки обработанных событий для дедупа |

Площадка в эту базу не ходит и про неё не знает.

## Переменные окружения

Полный список с дефолтами — в [`.env.example`](../.env.example) в корне
репозитория, раздел «venue-service». Самое важное:

| Переменная | Смысл |
|---|---|
| `PARTNER_BASE_URL` | адрес партнёрского API площадки |
| `PARTNER_API_KEY` | ключ, выданный заведению при онбординге (`vk_demo_bakery_dev`) |
| `KAFKA_ORDERS_TOPIC` | топик, из которого заведение читает свои заказы |
| `AUTOPILOT_ENABLED` | выключить автопилот и вести заказы руками |
| `AUTOPILOT_*_AFTER` | сколько заказ проводит в каждом состоянии |

## Как посмотреть, что он делает

```bash
docker compose logs -f venue-service

docker compose exec venue-postgres psql -U venue -d venue \
  -c "select main_order_id, state, state_changed_at from incoming_orders order by received_at desc limit 5"

docker compose exec venue-postgres psql -U venue -d venue \
  -c "select sku, stock, is_available from dishes"
```

Заказ, созданный в пекарне на площадке, за десяток секунд пройдёт
`ACCEPTED → COOKING → READY → DELIVERING`, а закроет его уже площадка.
